<task type="auto">
  <name>Task 1: Create expected transfer models and CSV expansion helpers</name>
  <files>
tests/simulation_logs/expectations.py
  </files>
  <action>
Create an ExpectedTransfer dataclass to represent ordered expectations with source and destination identifiers. Include: sequence_index, source_labware_id, source_slot, source_well, dest_labware_id, dest_slot, dest_well, aspirate_volume_ul, dispense_volume_ul, and optional group_id/group_total_volume_ul for distribution rows. Implement helpers:
- parse_csv_rows(csv_path) using csv.DictReader and preserving order.
- detect_home_row(row) matching the HOME control rules from validation (all non-empty cells == HOME).
- parse_labware_field("labware_id_slot") -> (labware_id, slot) by splitting trailing numeric segment.
- derive_mode(settings) from settings["settings"]["general"]["mode"].
- build_expected_transfers(csv_path, settings):
  - Skip HOME rows entirely.
  - Detect distribution rows when Dest Well contains '|' or Distribution Volume (ul) present.
  - For distribution rows: split dest wells by '|', compute per-dest volumes (equal or geometric pattern). Use the CSV Distribution Volume (ul) as base, apply factor sequentially (geometric:factor), and respect optional :asc/:desc by ordering the generated list. Create one ExpectedTransfer per dest well with shared group_id and group_total_volume_ul set to the sum of per-dest volumes. Use aspirate_volume_ul = group_total_volume_ul and dispense_volume_ul = per-dest volume (+ Air Gap if provided).
  - For non-distribution rows: use Volume (ul) and apply Air Gap to dispense_volume_ul (aspirate_volume_ul remains CSV volume).
  - For mode handling: single_X1 and multi_X1 produce one ExpectedTransfer per CSV row; multi mode does not expand to A-H wells (expectations stay at the CSV well).
  - Assign sequence_index in CSV order, with distribution expansions ordered by dest well list.
  </action>
  <verify>Open tests/simulation_logs/expectations.py and confirm HOME handling, distribution expansion, and air gap adjustments are implemented as specified.</verify>
  <done>Expectation builder returns ordered ExpectedTransfer entries for all modes and special cases.</done>
</task>
